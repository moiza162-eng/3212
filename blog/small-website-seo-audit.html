How to run an SEO audit on a small website

Start with the pages that matter

Pick a small sample: the homepage, the main service pages and the page where people enquire or book. For each one, write down the action the page should support and the type of search that might bring someone there. A course page should help a prospective learner assess eligibility, understand the schedule and register. A contact page has a different job.

Check discovery and usefulness

Open each page from the site navigation and on a phone. Check that internal links work and that the title and main heading describe the same offer. If you have Search Console access, use URL Inspection to check the indexed URL and compare it with the URL you intend to show in search. Record the evidence beside each finding, including the affected URL and the date you checked it.

Prioritise the fixes

Put blocked journeys ahead of cosmetic improvements. A broken registration link deserves attention before a slightly repetitive heading. For each fix, record the owner, the expected improvement and how you will check it. Re-test the journey after publication, then compare organic clicks and enquiries with a baseline. The Intech Centre audit illustrates how to turn public observations into recommendations.

Follow the path from search to enquiry

Imagine a learner arriving directly on a course page after searching for evening classes. They may never see the homepage. Read the page in that order and check whether they can tell which qualification it offers, where teaching happens and how to register. Then follow the registration link. Record what happens after submission, including whether confirmation explains the next step. Repeat the journey from another entry point, such as a guide or the contact page. This often reveals an issue that checking pages individually misses. For example, a guide may still point to last year's course even though the main navigation links to the current programme. Save the exact source and destination so the link can be corrected quickly.

Separate access problems from editorial problems

Write down whether your priority pages return a working response and whether any redirect ends at the intended page. Check that the URLs included in the sitemap are the versions you want indexed. If a page has a canonical URL different from the one you expected, check whether the declared URL is intentional before recommending a change. Changes to redirects and canonical tags can affect more than one page, so agree the desired destination with the site owner first. Keep an editorial issue such as an unclear title in a separate row. That distinction helps the team assign the work correctly and avoids changing technical settings when the real issue is simply that a visitor cannot understand the offer.

Write findings someone can reproduce

For each finding, include the page, the evidence, the user affected and the proposed change. For example, record that the mobile course page links to a general directory under a button labelled Apply, and that the reader must search the directory for the same course. Propose a direct link to the correct registration form and check the destination with the admissions team. Add a completion criterion that anyone can test after release. In this case, the button should open the right form on a phone and the form should identify the relevant course. Save screenshots only where they clarify the issue, and keep any personal information out of your evidence.

Review results in stages

Immediately after release, verify that links, titles and enquiry journeys work as expected. Later, compare changes in clicks for the affected pages and in confirmed enquiries. Use comparable dates and record other activity such as a new advertising campaign or enrolment deadline. If clicks improve but enquiries are flat, look at the questions people ask and whether the traffic reaches the relevant registration page. An audit can surface a useful next question even when the first round of fixes produces little movement. Keep the baseline and the change log together so the next reviewer can see which pages were fixed, when they changed and what evidence is still missing. This also makes it easier to revisit recommendations when a site launches a new programme. Schedule that review now.
